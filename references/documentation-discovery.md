# Documentation Discovery and Placement

Before creating a record, inspect project instructions, existing documentation, similar feature records, templates, PR/Issue conventions, ADR or RFC directories, and any generated documentation policy.

Prefer, in order:

1. the project's explicitly documented location and template;
2. an existing record for the same feature or change;
3. the project's established docs, ADR, RFC, issue, or pull-request workflow;
4. a minimal new record using this skill's templates only when no project convention exists.

Do not create a second documentation system merely because the default templates are convenient. Adapt headings and filenames to the project. Bind records to the relevant issue, PR, branch, commit, or release when that is already customary.
