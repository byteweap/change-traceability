# Deviations, Assumptions, and Risks

Record material differences between the requested behavior and the delivered behavior.

| Item | Requested or assumed | Actual result | Reason | Confirmed? | Follow-up |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

An implementation deviation is not automatically a defect, but an undocumented deviation is an accountability risk. Mark unresolved requirements as assumptions or items requiring confirmation rather than presenting them as confirmed business rules.
